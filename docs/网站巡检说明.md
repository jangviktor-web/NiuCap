# 网站巡检 —— 定时检测 + 故障告警

## 它解决什么问题

平台自带的健康检查只看「端口有没有人监听」。它发现不了这些情况：

| 故障 | 平台探针 | 本巡检 |
|---|---|---|
| 服务监听错端口（如 8000 vs 8899） | ❌ 探不到 | ✅ 抓到 |
| 进程活着但行情没加载 | ❌ 以为正常 | ✅ 抓到 |
| 页面 500 / 接口报错 | 部分 | ✅ 抓到 |
| 沙箱休眠中 | ❌ 不区分 | ✅ 抓到 |
| 响应极慢 | ❌ 不响应才算挂 | ✅ 记为提示 |

## 快速开始

```bash
# 跑一次，看报告
python3 scripts/health_check.py

# 机器可读（供计划任务消费）
python3 scripts/health_check.py --json
```

退出码：`0` = 正常或首次异常（防抖中），`1` = 已确认故障。

## 它检查什么

| # | 项目 | 判定标准 | 是否致命 |
|---|---|---|---|
| ① | 首页可访问 | HTTP 200 且正文 > 5KB | ✅ 致命 |
| ② | 接口健康 | `/api/health` 返回 `ok:true` | ✅ 致命 |
| ③ | 行情已加载 | `market_count > 0` | ✅ 致命 |
| ④ | 数据合理性 | 无服务端 error、数值在合理区间 | 仅提示 |
| ⑤ | 响应耗时 | < 8 秒（冷启动超时属正常） | 仅提示 |

**防抖**：单次失败不算故障（网络抖动、沙箱冷启动都会造成偶发超时）。
连续 **2 次**失败才判定故障 —— 既避免误报，也能在下一轮确认。

## 定时执行

### 你自己电脑上（推荐）

沙箱 10 分钟无访问就会休眠，装在里面会漏检。跑在自己电脑上最可靠 ——
它探测的是公网地址，沙箱睡不睡都能测。

**Windows（任务计划程序）**

1. 打开「任务计划程序」→ 创建基本任务
2. 触发器：每天，重复间隔 **1 小时**，持续时间「无限期」
3. 操作：启动程序
   - 程序：`python`（或你的 Python 完整路径）
   - 参数：`D:\path\to\tick-stock-panel\scripts\health_check.py`
   - 起始于：`D:\path\to\tick-stock-panel`
4. 勾选「不管用户是否登录都要运行」

命令行一行版（管理员 PowerShell）：

```powershell
schtasks /create /tn "Tick巡检" /tr "python D:\path\to\scripts\health_check.py" ^
  /sc hourly /mo 1 /f
```

**macOS / Linux（crontab）**

```bash
crontab -e
# 加入这一行：每小时整点跑一次
0 * * * * cd /path/to/tick-stock-panel && /usr/bin/python3 scripts/health_check.py >> /tmp/tick-health.log 2>&1
```

### 在服务器/沙箱内（补充）

```bash
python3 scripts/health_check.py --loop --interval 60
```

⚠️ 注意：沙箱休眠时这个进程也会跟着睡，实际可能几小时才真检一次。
适合作为补充，不适合作为唯一保障。

## 告警怎么看

**告警日志**：`data/health_alerts.log`

```
[2026-09-21 17:32:53] ❌ 故障告警：https://xxx.app.workbuddy.host —— 首页可访问: 请求超时（25s 无响应）
[2026-09-21 17:33:01] ✅ 已恢复：https://xxx.app.workbuddy.host（此前连续失败 4 次）
```

**页面提醒**：打开面板，右上角会显示状态

- `✅ 运行正常` —— 最近一次巡检通过
- `🚨 巡检异常 N 次` —— 确认故障，点开看详情

没跑过巡检时**不显示任何角标**，不打扰。

## 为什么不自动修复

这是刻意的设计，不是没做完。

**原因一：大部分故障重启治不好。** 2026-09-21 那次「打不开」的根因是
服务监听 8000 而平台转发 8899 —— 自动重启只会把错端口的进程再拉起来一次，
重启一百次也好不了。修好它靠的是改配置。

**原因二：判断「该不该重启」的信号不可靠。** 沙箱冷启动要几秒，
网络抖动也会超时。为这点小事自动重启，容易把本来正常的服务折腾出问题。

**原因三：自动改代码风险极大。** 如果让机器自动「修复」逻辑 bug
（比如均线只画一半那类），它可能悄悄把一处小错改成另一处你没发现的错，
而且是在你不知情的时候。

所以本巡检的定位是：**快速发现 + 明确告警，修复动作由人确认后执行。**

## 实测记录

| 场景 | 结果 |
|---|---|
| 正常站点 | 5 项全过，结论「正常」 |
| 错误端口（复现真实故障） | 首页致命失败，跳过后续检查 |
| 域名不存在 | 抓取到 DNS 解析失败 |
| 连续失败 4 次 | 第 2 次才告警，第 3/4 次不重复刷屏 ✅ |
| 故障后恢复 | 写明「已恢复」，清除告警状态 ✅ |
| 退出码 | 首次异常 0，已告警 1 ✅ |
