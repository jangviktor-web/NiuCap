## 2. 功能方案

三个功能按价值排序，**建议只做 F1，F2 视你需求，F3 可缓**。

### F1 · ETF 网格回测（推荐，价值最高）

新增 `server/grid.py`（约 200 行）+ 前端页（约 150 行）+ 自检（约 80 行）。

**为什么不整仓移植 grider**：它是 React + Flask 双工程、要 Tsanghi API key、数据源跟我们不一样。我们只需要它的 `algorithms/` 那 800 行算法，其中真正要抄的只有网格档位计算 + 撮合推进，约 150 行。**指标计算复用现有 `backtest.py` 的 FIFO 撮合和净值口径**，不重复造。

接口：

```
GET  /api/grid/backtest?code=sh510300&step=2&band=20&lot=10000&capital=100000
     → { levels:[...], trades:[...], metrics:{ 收益/回撤/夏普/触发次数/资金利用率 },
         bench:{ 买入持有收益 }, warnings:[...] }
GET  /api/grid/suggest?code=sh510300     → 按 ATR 给建议步长/底仓比例
```

参数：基准价（默认最新收盘）、步长%（等差）或步长比（等比）、上下界（默认 ±20%）、每格份数（默认 10000，ETF 一手 100 份）、总资金、底仓比例、费率（**复用虚拟盘那套用户自定义费率**）。

不登录也能用（与选股一致，只拦虚拟盘）。

### F2 · ETF 筛选器

新增 `server/etf.py`（约 180 行）+ 前端页（约 120 行）。

- 清单：新浪接口 1676 只，落本地表，每日随调度刷新
- 快照：腾讯批量（1600 只 ≈ 8s），可实时筛
- 筛选维度：**规模下限、成交额下限、涨跌幅、换手率、上市数据长度**、按动量/规模/成交额排序
- **做不了的**：IOPV、折溢价率（源不通，见 4.2）

### F3 · 网格实盘档位表（可缓）

etf-dashboard 那套「建网格 → 当前价驱动档位判断（🟥买/🟩卖/➖持）→ 手动确认成交」。挂在虚拟盘下，需要登录。价值中等，建议 F1 上线后看反馈再定。

## 3. 已实测发现的 bug（移植前必须修）

这些不是"可能"，是本机跑出来的。

### B1 · 已实现盈亏算错（严重）

`trading_logic._execute_sell` 用
`avg_cost = (state.total_asset - state.cash) / state.position`
倒推成本，而 `total_asset` 在买入时被写成 `cash + position * price`，**所以 avg_cost 恒等于最后一次成交价**，不是加权平均成本。

实测：

```
买 100 @5.0，再买 100 @4.0（真实平均成本 4.5），卖 100 @4.5
真实盈亏  +0.00
代码算出  +50.00   ← ❌
```

**修法**：单独维护 `avg_cost` 字段，买入时 `avg_cost = (avg_cost*pos + price*qty) / (pos+qty)`，卖出时不动 avg_cost、只减份额，已实现盈亏 = `(卖价 - avg_cost) * qty - 费用`。跟 `store.py` 里虚拟盘的加权成本口径保持一致。

### B2 · 单根 K 线双方向只成交一边

`check_and_execute` 先判买入，成交就 `return`，卖出分支被吞。

实测：K 线 `low=4.7`（< 买点 4.9）且 `high=5.3`（> 卖点 5.1），双向都该触发 → **实际只买不卖**。

**修法**：一根 K 线内先按 `low` 逐级吃买单，再按 `high` 逐级吃卖单，循环到不再触发为止。注意顺序：先买后卖会让同一根线出现"买了立刻卖"，实际应按「先低后高」的时间假设不可知，取保守口径 —— 只吃靠近开/收盘的一侧，或明确标注为「日线级简化」。

### B3 · 网格触发率指标定义错

`_calculate_grid_trigger_rate = 交易笔数 / 网格数`，实测算出 **1.4**（>1，概念上就不该超过 1）。交易笔数天然可以远多于网格数。

**修法**：改成 `触发过的不同档位数 / 总档位数`，或者干脆砍掉这个指标（YAGNI：你现在没用它做决策）。

### B4 · 契约不一致（我踩了一次）

`MetricsCalculator.calculate_all(price_curve=...)` 内部取 `price_curve[0]['close']`，但参数名和文档都暗示是价格序列。**传 `{'time','price'}` 直接 `KeyError`**。

**修法**：我们自己写时直接用 `{'time','close'}`，并在函数签名上写清楚。

### 非 bug 但必须让用户知道的行为

实测单边行情（这是网格策略的固有特性，两个仓库都没提示用户）：

| 场景 | 行情 | 网格结果 |
|---|---|---|
| 单边上涨 | +81.67% | **+8.85%**（只成交 2 笔，突破上界后停摆踏空） |
| 单边下跌 | -45.28% | **-40.08%**（一路买满，现金耗尽） |

**修法**：回测结果里必须带回 `warnings` 字段，明确提示「本区间为单边行情，网格策略不适用，收益来源于震荡」。否则用户会拿一段牛市回测当策略有效。

## 4. 落地时预判会踩的坑 + 解法

### 4.1 数据源突然不通

三个源都可能挂（东财已经挂了）。

**解法**：清单接口加三级兜底 —— 新浪清单 → 本地 `etf_list` 表（上次成功的快照）→ 空。兜底命中要在返回里带 `source: "cache" / 数据时间`，前端显示"数据可能不是最新"。**静默回落到陈旧数据比报错更危险**，这条跟之前修的交易日判断是同一类问题。

### 4.2 IOPV / 溢价率做不了

etf-dashboard 的画像页靠东财 `fund_etf_spot_em` 的「IOPV实时估值」「基金折价率」两个字段，**本机不通**。

**解法**：三种选择，建议选 A。
- **A. 直接不做**，筛选页不显示这两列，不做假数据（推荐）
- B. 留空位显示"—"并注明"需东财源"
- C. 换源（需另找支持 IOPV 的接口，我没找到免费的）

**绝对不能做的**：用净值估算溢价率糊一个。错的数比没数更害人。

### 4.3 ETF 最小交易单位与整手

ETF 一手 = 100 份，但 grider 写死 `min_trade_unit = 100`（美股 1）。**如果以后加港股/美股要参数化**，现在只做 A 股就写死常量，别提前抽象。

### 4.4 复权口径

etf-dashboard 明确说了用**不复权** OHLCV。ETF 分红会导致价格跳空，网格回测里会被误判成"跌了一格"从而触发买入。

**解法**：回测用不复权（跟实盘看到的价格一致），但**在分红除息日附近过滤掉异常跳空**，或在结果里标注。至少要有 awareness，不能假装没这回事。

### 4.5 与现有代码的冲突点

- `newbie.py` 主动**排除** ETF（关键词过滤 "基金"/"ETF"）—— 新手推荐池不要误加 ETF
- `store.py` 的 `is_etf` 用代码段前缀 `sh5/sz15/sz16/sz18` 判定，网格回测要复用这个判定来走 ETF 费率（免印花税）
- 调度器目前 250 只股票池，加 ETF 池要考虑**耗时**：日线串行 0.47s/只，1600 只 12 分钟，**不能塞进 15:30 那次同步**，要单独排（比如 16:30）

### 4.6 浮点与精度

网格档位是 `基准价 ± n×步长`，浮点累加会漂移。grider 的做法是 `round(price, 3)` 去重（阈值 0.001）。ETF 价格普遍 0.7~5 元，**3 位小数可能不够**（步长 2% 在 1.0 元的 ETF 上是 0.02，够；但 0.5% 步长是 0.005，去重阈值 0.001 会误合并）。

**解法**：去重阈值改成 `步长 / 10`，别写死 0.001。

### 4.7 前端性能

1676 只 ETF 全量渲染会卡。

**解法**：默认只渲染筛选后的 Top N（50 只），跟现有自选股列表一致的虚拟滚动或分页。
