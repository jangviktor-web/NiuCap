# 技术指标三表口径对照（TradingView vs 本面板）

> 目的：说清楚「为什么两边数字不一样」，以及在什么条件下**应该**一样。
> 相关代码：`server/tv_rating.py`（仪表口径）、`server/indicator_rating.py`（明细表口径）。

## 一、两套口径并存，分工不同

| | 仪表（三张半圆盘） | 明细表（全套技术指标） |
|---|---|---|
| 代码 | `tv_rating.py` | `indicator_rating.py` |
| 指标数 | 26 项 | 61 项 |
| 判定方式 | **事件/状态**（如 RSI 上穿 70） | **水平阈值**（如 RSI > 70） |
| 分档 | 五档（强买/买/中立/卖/强卖） | 三档（买/卖/中立） |
| 目的 | 与 TradingView 对读 | 自有分析工具 |

**为什么不能合成一套**：RSI 在两种语义下结论相反。事件判定下，RSI 长期停在 75 也只在「上穿 70」那一次投卖票，其余时间中立；水平判定下，只要 RSI > 70 就持续投卖票。混进同一套票数，两边都会失真。

## 二、TradingView 的构成（官方口径）

来源：<https://www.tradingview.com/support/solutions/43000614331>

**均线组 15 项**
- SMA × (10, 20, 30, 50, 100, 200) — 6 项
- EMA × (10, 20, 30, 50, 100, 200) — 6 项
- HullMA(9)、VWMA(20)、一目均衡(9, 26, 52) — 3 项

**震荡组 11 项**
RSI(14)、Stochastic(14,3,3)、CCI(20)、ADX(14,14)、Awesome Oscillator、
Momentum(10)、MACD(12,26,9)、Stochastic RSI、Williams %R(14)、
Bull Bear Power(13)、Ultimate Oscillator(7,14,28)

**总结 = (均线组均值 + 震荡组均值) / 2**，两组等权。
**不是** 26 项混算——这一条最容易写错，因为两组票数不同（15 vs 11）时两者结果不等。

**分档**（均值落在 [−1, 1]）
| 区间 | 档位 |
|---|---|
| < −0.5 | 强烈卖出 |
| [−0.5, −0.1) | 卖出 |
| [−0.1, 0.1] | 中立 |
| (0.1, 0.5] | 买入 |
| > 0.5 | 强烈买入 |

## 三、逐指标判定规则（实现里必须照抄的部分）

| 指标 | 买 | 卖 |
|---|---|---|
| SMA/EMA/HMA/VWMA | MA < 现价 | MA > 现价 |
| 一目均衡 | 先行A>先行B 且 基准>先行A 且 转换>基准 且 现价>转换 | 全部反向 |
| RSI(14) | **上穿** 30 | **上穿** 70 |
| Stochastic | %K 上穿 %D 且 %K<80 | %K 下穿 %D 且 %K>20 |
| CCI(20) | 上穿 −100 | 上穿 +100 |
| ADX(14) | +DI>−DI 且 ADX>20 且 ADX 上升 | 镜像 |
| AO | 上穿 0 轴 | 下穿 0 轴 |
| Momentum(10) | 上升 | 下降 |
| MACD | DIF > DEA | DIF < DEA |
| StochRSI | %K>%D 且 %K<20 且 %K 上升 | 镜像 |
| W%R(14) | %R<−80 且上升 | %R>−20 且下降 |
| BBP(13) | 上升趋势 且 BearPower<0 且上升 | 镜像 |
| UO | >70 | <30 |

「上穿」是**事件**：要求上一根还在阈值下方或等于。一直高于阈值不算上穿。

## 四、实测对照（峰岹科技 SH688279，日线）

用户提供的 TradingView 截图 vs 本面板实现：

| 表 | TradingView 截图 | 本面板 | 一致性 |
|---|---|---|---|
| 震荡指标 | 0 卖 / 9 中 / 2 买，**中立** | 1 卖 / 8 中 / 2 买，**中立** | 档位一致，差 1 票 |
| 移动平均线 | 0 卖 / 1 中 / 14 买，**强烈买入** | 0 卖 / 1 中 / 14 买，**强烈买入** | **逐项一致** |
| 总结 | 0 卖 / 10 中 / 16 买，**强烈买入** | 1 卖 / 9 中 / 16 买，**强烈买入** | 档位一致，差 1 票 |

差 1 票的可能原因（未定论）：K 线取样区间不同、ADX 的 `M2=14` 平滑细节、
TradingView 的「碟形」判定（AO 的 saucer 形态）未实现。

## 五、已知不确定：分档阈值

截图里震荡组是 2 买 / 9 中 / 0 卖，均值 = 2/11 = **+0.1818**。
按官方 ±0.1 / ±0.5 阈值应判「买入」，但页面显示「中立」。

**单张截图无法反推阈值**（一个观测点约束不了一条边界），因此：
- 实现按官方文档的 ±0.1 / ±0.5；
- 常量集中在 `tv_rating.py` 顶部 `THRESH_STRONG` / `THRESH_WEAK`；
- 若后续拿到更多样本证明阈值更宽（试算 ±0.2 或 ±0.25 都能解释该截图），只改这两个常量。

## 六、我们没有做的部分

- **AO 的碟形（saucer）判定**：只实现了「上穿/下穿 0 轴」。碟形需要识别
  连续两根同向柱加一根缩量柱的形态，实现复杂度高于其余全部指标之和，
  且只影响 1 票（占 26 项的 3.8%）。
- **多周期**：只算当前选中周期（日线/周线等），不做 TradingView 那样的
  1分/5分/15分/…/1月 九档并排。

## 七、如何验证

```bash
cd server && ../.venv/bin/python tv_rating.py       # 规则自检
cd .. && .venv/bin/python tests/smoke_stock_viz.py  # 端到端（含口径契约断言）
```

`smoke_stock_viz.py` 里有三条钉住口径的断言，任一条破掉都说明退回了旧算法：
1. 震荡组必须 11 项、均线组必须 15 项、总结必须 26 项；
2. 总结必须等于 `(震荡均值 + 均线均值) / 2`；
3. **所选股票必须能区分「等权」与「混算」**（两者差 > 0.02），
   否则该用例自动失败——防止再出现「选到一只两种算法恰好重合的票」的假绿。
