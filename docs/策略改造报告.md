### 第 3 层：过程审计 —— 发现并修复两处真实缺陷

第一轮交叉验证时出现 **15 处分歧**。逐个追查后发现**不是 pandas 脚本的问题，
而是模块的真实缺陷**。这两处是本次改造最有价值的发现：

#### 缺陷 A：float32 边界比较误判「平前高」为「破前高」

**现象**：模块命中 450 只，pandas 命中 444 只，多出 6 只。

**根因**：历史序列以 float32 存储（省一半内存），`5.10` 被存成 `5.09999990`。
判断「当日最高 5.10 是否突破前 20 日高 5.10」时：
- 模块：`5.10 > 5.09999990` → True → 误判为突破
- pandas：`5.10 > 5.10` → False → 正确地判为「平前高，未突破」

**量化影响**：

```
450 只命中里，突破幅度 < 1e-6（float32 噪声级）的: 6 只
              突破幅度中位数: +2.06%
              突破幅度 P10   : +0.30%
```

即：真正有效的突破都有 +0.3% 以上的幅度，那 6 只实际上是**恰好等于前高**。

**修复**：新增带容差的比较函数，`EPS = 1e-5`。

```python
# server/screener.py
_EPS = 1e-5

def _gt(a, b):
    """a 显著大于 b。用于突破 / 新高 / 站上均线。"""
    return a > b * (1.0 + _EPS) if b != 0 else a > 0

def _lt(a, b):   # 用于创新低 / 跌破
    return a < b * (1.0 - _EPS) if b != 0 else a < 0

def _ge(a, b):   # 用于「价格站上均线」（允许相等）
    return a >= b * (1.0 - _EPS) if b != 0 else a >= 0
```

为什么 `EPS=1e-5` 是安全的：A 股最小价格变动单位是 0.01 元。
1e-5 的相对容差在 10 元股价上约合 0.0001 元、在 1000 元股价上约合 0.01 元，
**远小于一个最小变动单位**，不会把真实的小幅突破误杀。

同时把均线求和提升到 float64（存储仍是 float32，只是计算瞬间提升）：

```python
# server/history.py
def _last_ma(arr, period):
    """序列以 float32 存储，但求和时提升到 float64。
    否则 20~60 个 float32 相加会让误差累积到 1e-6 量级，
    导致「价格刚好站上均线」这类等值比较出现随机翻转。"""
    return float(np.mean(arr[-period:].astype(np.float64, copy=False)))
```

**效果**：突破新高 450 → **444**（与 pandas 完全一致）。

#### 缺陷 B：区间振幅把「当日」算了进去

**现象**：平台突破模块命中 34 只，pandas 命中 39 只，且**分成两个方向的分歧**。

**根因**：`range60_pct` 用 `_range_pct(H, L, 60)`，取的是**含当日**的最后 60 根。
但平台突破问的是「**突破之前那段时间横不横**」—— 当日往往是放量大涨的那根，
把它算进去，振幅会被当日自己撑大。

**实测证据**（这就是被误杀的股票）：

| 代码 | 名称 | 不含当日振幅 | 含当日振幅 | 结果 |
|---|---|---|---|---|
| `sh600640` | 国脉文化 | **26.3%** | **38.2%** | 含当日 > 35% → 误杀 |
| `sz000532` | 华金资本 | 34.0% | 47.5% | 误杀 |
| `sz000829` | 天音控股 | 33.7% | 38.6% | 误杀 |
| `sz300559` | 佳发教育 | 33.1% | 35.0% | 卡在阈值上 |
| `sz300708` | 聚灿光电 | 31.9% | 37.9% | 误杀 |

仅因窗口差一根 K 线，振幅虚增 **3~12 个百分点**，足以让合格平台突破出局。

**修复**：改为不含当日，与同模块的 `hhv60`/`llv20` 口径统一。

```python
# server/history.py
# 注意：一律不含当日。hhv20/hhv60/llv20 早已如此，range 也须一致。
if w("range20_pct"):
    m["range20_pct"] = _range_pct(H[:-1], L[:-1], 20)
if w("range60_pct"):
    m["range60_pct"] = _range_pct(H[:-1], L[:-1], 60)
```

**效果**：平台突破 34 → **39**（与 pandas 完全一致）。

#### 剩余「分歧」的排除

修复后仍有 6 处分歧（`ma_bull` 1 只、`platform_break` 5 只），追查后确认为
**测试脚本口径不同**，不是模块问题：

- `sh603400`（华之杰）：快照 `high=0.0`、`amount=0.0` —— 是「**已发行未上市**」的新股。
  策略里的 `amount <= 0 → continue` **正确地排除了它**，而我的 pandas 脚本起初没加这个检查。

补上口径后，分歧归零。

### 第 4 层：阈值敏感性 —— 用数据选阈值，不拍脑袋

平台突破的振幅阈值 `35%` 是经过实测敏感性分析确定的：

| 振幅上限 | 命中数 | 占比 | 命中名单振幅中位 |
|---|---|---|---|
| ≤20% | 5 | 0.13% | 15.1% |
| ≤25% | 15 | 0.40% | 21.3% |
| ≤30% | 30 | 0.80% | 25.0% |
| **≤35%** | **39** | **1.0%** | **25.9%** | ← 采用 |
| ≤40% | 49 | 1.30% | 27.9% |
| ≤45% | 58 | 1.54% | 33.5% |
| ≤50% | 66 | 1.75% | 34.8% |

**选 35% 的理由**：

1. 「平台」的核心语义就是**横盘**。命中名单的振幅中位仅 **25.9%**，
   说明真实平台突破的振幅天然远离 35% —— 阈值并未卡在边缘，而是留足余量。
2. 放宽到 45% 只多 22 只（+0.6%），但这 22 只的振幅集中在 36%~43%，
   已属「宽幅震荡」而非「平台」，会稀释策略纯度。
3. 反向验证：35%~45% 区间的 22 只「准命中」中，多数距前高仅 +0.5%~+2%，
   形态上是「贴着上沿的宽幅震荡」而非「突破平台」，语义不符。

回踩企稳同样经过敏感性测试：

| 偏离区间 | 量比上限 | 命中占比 |
|---|---|---|
| ±1.5% | ≤0.8 | 8.1% |
| **±2%** | **≤0.85** | **~11.8%** | ← 采用 |
| ±3% | ≤1.0 | 22.0% |

±3%+量比≤1.0 会放过 22% 的股票，失去筛选意义；±1.5%+量比≤0.8 过严。
取 ±2% + 量比≤0.85。

## 四、遗留事项

| 事项 | 说明 | 状态 |
|---|---|---|
| **首次扫描延迟** | 首个历史策略请求需触发引擎加载（全表读 + 指标计算），此窗口内可能返回空结果 | ✅ **已解决**：`app.py` 启动时后台预热，实测首帧 **0.09s**（预热前数秒） |
| **🔴 盘中快照与历史差一个交易日** | 历史日线最新是**上一交易日收盘**，快照是**当日盘中**；盘中跑策略会把「今日价」与「截至昨日的指标」混用，命中数漂移（`breakout_20h` 444→568、`platform_break` 39→19） | ⚠️ **未处理**，详见 [会话交接文档 §6.1](./会话交接文档_策略改造.md)。盘后跑完全准确 |
| 平台突破 39 只是否偏少 | 当前阈值偏严但不失真（命中质量高） | 保留；如需更多标的可放宽到 40%（49 只） |
| 北交所纳入策略池 | 历史库已有 344 只北交所，但快照池 `pool_rows()` 只有 3761 只（缺 1814 只北交所/次新） | 后续可把 `pool_rows()` 扩展到 eltdx 全量代码表 |

### 关于盘中日期错位（重要）

**已实测验证的对齐关系**（2026-09-22 盘中抽查 400 只）：

```
历史末根收盘 == 快照 prev_close 的: 398 只
不相等的: 2 只（sh600379、sh600429，均为除权 XD 股）
```

即：**历史日线的最后一根 = 快照的「昨收」**，两者确实差一个交易日。

因此：
- **盘后运行**（推荐）：当日日线已落库，快照与历史同日 → 结果准确
- **盘中运行**：指标基于昨日，当日涨跌未纳入 → 命中数会漂移

处理方向（P0，见交接文档）：API 透出 `data_lag_days` + 前端提示「指标截至昨日」。

### 预热实现

```python
# server/app.py
def _warm_history():
    """首个带 "hist" 的策略请求需触发全表加载（约 3.3s）+ 全市场指标计算。
    若不预热，用户第一次点「突破新高」会卡几秒，且此窗口内可能返回空结果
    （看起来像「没有股票符合」）。"""
    try:
        import history as _hist
        t0 = time.time()
        eng = _hist.get_engine()
        st = eng.stats() or {}
        print(f"[history] 历史指标引擎已预热：{st.get('codes')} 只 / "
              f"{st.get('rows')} 行 / {time.time() - t0:.2f}s / 最新 {st.get('as_of')}")
    except Exception as e:
        print(f"[history] 预热失败（历史类策略首次调用时会再试）：{e}")

@app.on_event("startup")
def startup():
    ...
    threading.Thread(target=_warm, daemon=True).start()
    threading.Thread(target=_warm_history, daemon=True).start()
```
