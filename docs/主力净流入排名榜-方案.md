# 主力净流入排名榜 —— 方案备忘（待实现）

> 状态：**已调研，未实现**。本文档是 2026-10-16 的调研结论 + 落地方案，
> 下次要做时从「实施清单」开始即可，无需重新调研数据源。
> 需求方原话：「主力流入排名榜单功能，我们的面板里面有没有？」

---

## 1. 需求

在市场榜单（现六大榜：涨幅/跌幅/成交额/换手率/市值/低估值）基础上，增加
**个股主力净流入排名**：全市场按当日主力净流入（或净占比）排序的榜单，
支持查看超大单/大单/中单/小单分层净流入。

## 2. 现状盘点（2026-10-16）

| 已有能力 | 口径 | 位置 | 是否满足需求 |
|---|---|---|---|
| 行业榜 | **行业级**主力净流入 + 5 日净额 | 市场热点页 `/api/sector_rank` | 否（缺个股级） |
| 个股资金流卡片 | **单票**主力/超大单/大单/中单/小单净额 + 5/10/20 日 + `MainInflowRank` | 个股分析页 `/api/fundflow?codes=` | 否（无排名列表） |
| 龙虎榜 | 营业部买卖 | 市场热点页 | 否（另一口径） |

**结论：个股级全市场主力净流入排名榜 = 没有，需新做。**

## 3. 数据源调研结论（实测证据，别再重复踩）

### 3.1 westock（腾讯自选股 CLI，面板现有源）—— 批量限流，不可全量

- 封装：`server/westock.py:248 fund_flow(codes)` → CLI `fund flow <codes逗号分隔>`
- 返回字段齐全：`MainNetFlow/JumboNetFlow/BlockNetFlow/MidNetFlow/SmallNetFlow`、
  `MainNetFlow5D/10D/20D`、**`MainInflowRank`（上游算好的排名）**、`MainInflowCircRate`
- **限流实测（2026-10-16 20:xx，3800 只池）**：
  - 20 只/批：静默 20s 后 → 20/20 成功
  - 40 只/批：**2 成功 / 38 `RATE_LIMITED`**
  - 100 只/批：0 条；500 只/批：0 条（且耗时 22s，逼近 `run_cli` 25s 超时）
  - 连续第二批 20 只（间隔 3s）：10/20 partial——**限流恢复需约 20s 静默**
- 结论：全市场 3800 只逐个查 ≈ 190 批 × 3s+ ≈ **10 分钟以上且越跑越限**，
  不能作为实时榜单的同步取数路径；只适合「小批量精选」（top 100~200 活跃股）。

### 3.2 东方财富 push2（业界标准源）—— 本沙箱 IP 被墙

- 榜单接口（东财「资金流向·主力排名」页 data.eastmoney.com/zjlx/list.html 实际调用）：
  ```
  GET https://push2.eastmoney.com/api/qt/clist/get
    ?pn=1&pz=50&po=1&np=1&fltt=2&invt=2
    &fid=f62                # 排序字段：f62=主力净额；f184=主力净占比
    &fs=m:0+t:6,m:0+t:80,m:1+t:2,m:1+t:23,m:0+t:81+s:2048   # 沪深京A全市场
    &fields=f12,f14,f2,f3,f62,f184,f66,f72,f75,f78,f81,f84,f87
    &ut=8dec03ba335b81bf4ebdf7b29ec27d15
  Headers: Referer: https://data.eastmoney.com/ ; 浏览器 UA
  ```
- 字段表：`f12`代码 `f14`名称 `f2`最新价 `f3`涨跌幅 `f62`主力净流入(元)
  `f184`主力净占比(%) `f66`超大单净流入 `f69`超大单占比 `f72`大单净流入
  `f78`大单占比 `f75`中单净流入 `f81`中单占比 `f84`小单净流入 `f87`小单占比
- 分页：`pn`/`pz`（单页最大 ~200？按 50 稳妥）；历史 5/10 日版在
  `push2his` 的 `api/qt/stock/fflow/daykline/get`（个股维度，非榜单）
- **实测：本沙箱 push2 / push2his / push2delay 全系 403（IP 级封锁，
  换 UA/Referer/httpx TLS 栈均无效）；`datacenter-web.eastmoney.com` 可达
  （200，龙虎榜报表 RPT_DAILYBILLBOARD_DETAILS 验证过），但没有个股资金流报表**
- ⚠ 这是**环境限制不是方案缺陷**：面板部署在国内服务器时该接口直接可用。
  实现时必须做「通了就用、403 自动降级」的双路，不能假定可用。

### 3.3 同花顺 hithink（面板现有源）

`server/hithink.py` 有涨停/跌停/炸板/龙虎榜/异动池，**无资金流排名接口**。
新浪 MoneyFlow 端点探测均 404（`MoneyFlow.ssl_*` 三个候选名）。

## 4. 方案设计

### 方案 A：活跃股主力榜（纯 westock，现在就能跑）

**思路**：全市场精确排名不可行 → 退而求「活跃股中的主力榜」。
主力大额净流入必然伴随高成交额，对成交额 top N 查资金流即可覆盖
真实的主力榜 top 50（漏网概率极低）。

- 取数：`ds.pool_rows('all')` 按 `amount` 降序取 top N（**N=200**）
- 分批：20 只/批，批间 `sleep 3~5s`，批内失败（RATE_LIMITED）不重试
  （降级部分覆盖），冷查总耗时约 30~50s
- 排序：按 `main_net` 降序取 top 50；净占比 = `main_net / 流通市值`
  （westock 有 `main_circ_rate` 可直接用）
- 缓存：结果缓存 60s（realtime TTL，与 changedist 口径一致）；
  冷查期间返回旧缓存 + `stale:true` 标记，前端显示「计算中」
- ⚠ 局限必须在 UI 上写明：「基于成交额 top 200 活跃股，非全市场精确排名」

### 方案 B：方案 A + 东财双路（推荐，一次开发两种环境覆盖）

**取数链**（按优先级自动降级）：

```
/api/fundflow_rank
  ├─ 1) 东财 push2 clist（fid=f62，pz=50，单次请求 <1s）
  │     → 成功：全市场精确实时榜，字段全（分层+净占比）
  │     → 403/超时/解析失败：落到 2)
  └─ 2) westock 活跃股 top 200（方案 A 路径）
        → 成功：活跃股榜（标注口径）
        → 也失败：503 + 前端「数据源暂不可用」
```

- 东财成功时缓存 60s；westock 路径成功时缓存 60s
- 东财响应里 `rc` 非 0 或 `data.diff` 空 → 视为失败走降级
- 排序切换：`fid=f62`（净额）/`f184`（净占比）两种，前端给切换按钮

### 口径标签（复用现有体系，别新造）

- 交易时段 → `window.mktLiveTag()`「实时」；收盘后当日 →「收盘」
- 盘前/周末/节假日 →「盘后」（东财 f62 是当日实时口径，这些时段返回的是
  上一交易日收盘值；westock 活跃股路径同理）
- 60s 轮询只挂 `mktHasToday()` 窗口（与市场温度/宽度/情绪周期一致）

## 7. 备注

- westock 的 `MainInflowRank` 字段是上游排名，但批量限流下只能覆盖部分股票，
  该字段失去意义——**自己按 main_net 排**
- 东财接口的 `ut` token 是页面内置公开值，若失效从
  `data.eastmoney.com/newstatic/js/zjlx/list.js` 里重新抓（搜 `clist/get`）
- 5 日/10 日主力净流入榜：westock 有 `MainNetFlow5D/10D`（同样受限流约束）；
  东财有对应 `push2his` 日线接口（个股维度）——二期再做，本期只做「今日」
