# 分钟级实时数据说明

> 功能范围：个股分钟 K 线（1m/5m/15m/30m/60m）+ 全市场分钟级选股扫描，
> 双数据源（eltdx 优先、腾讯降级）。
> 本文说明数据从哪来、怎么缓存、哪些是实测踩过的坑、以及怎么验证它是对的。

## 〇、入口在哪（2026-09 整合后）

**原「⏱️ 分时看盘」独立页签已删除**，功能并入两处，避免重复入口：

| 功能 | 现位置 | 操作 |
|---|---|---|
| 单只票分钟 K 线 | **个股分析**页 → 「K线走势」卡片 | 右侧周期按钮 `日K/周K/月K ｜ 1分/5分/15分/30分/60分`，点了**就地换图** |
| 深度指标（区间位置/量比/均线排列/内外盘） | 同上，**图表上方一行摘要** | 鼠标悬停显示完整数字（开高低、MA5/MA20、量价结论） |
| 全市场分钟级选股 | **条件选股**页 → 「分钟级选股（全市场实时）」卡片 | 选预设 + 周期 → 开始扫描；点结果行直接进个股页并带入该周期 |

两条交互细节（都踩过）：

- **再点一次同一个分钟按钮 = 退回日线**。否则点了分钟就找不到回去的路。
- **高亮必须跟着图表数据源走**。曾出现「日K 高亮但画的是 30 分钟线」——原因是渲染时读了一个
  已废弃的 `state.intraPeriod`。现在日/周/月按钮在分钟模式下不高亮，优先级取反判断。

（截图：`docs/shot-stock-minute.png`）

## 一、整体架构

```
                ┌──────────────┐
   5m~60m ────► │  eltdx（主） │──┐
                └──────────────┘  │   统一入口
   1m     ────► │  eltdx（唯一）│──┼─► datasource.get_kline_intraday()
                └──────────────┘  │   （TTL 15 秒缓存，空结果不缓存）
                ┌──────────────┐  │
   降级        │ 腾讯 mkline  │──┘
                └──────────────┘
                ┌──────────────┐
   快照        │ eltdx 批量   │──► datasource.snapshot()
                │ (80 只/批)   │    （eltdx 优先，腾讯降级；TTL 3 秒）
                └──────────────┘
```

| 能力 | eltdx | 腾讯 | 说明 |
|---|---|---|---|
| 5m~60m 分钟线 | ✅ 批量 | ✅ 单只 | 主走 eltdx，失败降级腾讯 |
| 1m 分钟线 | ✅ | ❌ 无 1m | 只有 eltdx 有 |
| 北交所分钟线 | ❌ | ❌ | 两家都不覆盖，前端有专项提示 |
| 实时快照 | ✅ 批量（80 只/批） | ✅ 批量 | 快照源可选，默认 eltdx 优先 |
| B 股 / ETF / 可转债快照 | 部分 | ✅ | 统一入口自动互补 |

## 二、关键设计决策（都是实测得出的）

### 1. 各周期默认根数不同

不同周期「一根」代表的时间差 60 倍，统一根数必然出问题：

| 周期 | 默认根数 | 覆盖 | 为什么 |
|---|---|---|---|
| 1m | 2400 | ≈10 个交易日 | 一天 240 根，取 400 根只够 1.6 天，MA60 会是「假均线」 |
| 5m | 800 | ≈17 个交易日 | |
| 15m | 800 | ≈50 个交易日 | |
| 30m | 800 | ≈100 个交易日 | |
| 60m | 800 | ≈200 个交易日 | |

接口上 `count=0` 表示「按周期自动」；用户显式传 `count` 则以用户为准。

### 2. 扫描根数与看盘根数分离（SCAN_COUNT=120）

扫描指标窗口最长 61 根（MA60 + vol_ratio20）。实测 100/200/400/800 根算出的
指标逐位相同，但耗时 10.8 / 16.9 / 31.4 秒——多取的根数纯属白等。
所以扫描固定取 120 根（留一倍余量），全市场扫描约 12 秒。

### 3. eltdx 快照单次上限 80 只（静默截断）

传 500 只只回 80 只，**不报错**。适配层按 80 只自动分片，单片失败跳过不拖垮整批。
实测 4000 只 3.6 秒，100% 覆盖。

### 4. 市场状态显式化

`/api/kline_intraday` 响应带 `market_state`：
`pre_open / auction / trading / lunch / closed / holiday`。
收盘时前端明确标注「🔒 已收盘，以下为 X 的当日完整走势」，并给出
`showing_previous_day`（数据最新日期不是今天时为 true）——绝不把收盘数据冒充实时的。
同时非交易时段自动刷新按钮禁用，避免白刷数据源。

## 三、代码有效性守卫（重要）

### 为什么需要

通达信协议对不存在的代码**不报错，而是返回别的标的的数据**：

```
sh999999 -> 上证指数的行情（3952.13）
sh999998 -> 4143.88
```

用户敲错一位代码，看到的是一份看起来正常、实际张冠李戴的行情——没有任何迹象提示出错。

### 怎么判

`datasource.is_valid_code(code)` 三层：

1. **指数白名单**：`sh000/sh950/sz399/bj899` + 通达信板块指数 `sh88x`（指数不在 A 股代码表里，只用代码表会全部误杀）；
2. **A 股代码表**：eltdx `all_a_shares()`，5575 只，缓存 1 小时；
3. **表外段探测**：代码表没覆盖但真实存在的段，用统一快照探测一次（结果缓存）。

表外段清单（都有实测依据）：

| 段 | 内容 | 为什么表里没有 |
|---|---|---|
| bj 43/83/87/88 | 北交所老段 | eltdx 代码表只含 920 段（349 只） |
| bj 92 | 北交所新段 | 在表里，无需探测 |
| sh900 / sz200 | B 股 | 代码表只收 A 股 |
| sh5 / sz15,16,18 | ETF / LOF / 场内基金 | 同上，分钟线实测可用 |
| sh11 / sz12 | 可转债 | 分钟线不支持（会得到 404），但代码有效 |
| sh204 / sz131 | 国债逆回购 | |

**注意**：不能对所有段开放探测——sh999999 也能探测成功（返回上证指数），
所以探测范围必须收窄到上表。校验器自己挂了（取不到代码表）时返回 True 不拦：宁可放过，不误杀。

### 归一化（normalize）踩过的坑

| 输入 | 旧行为 | 问题 | 现在 |
|---|---|---|---|
| `920002` | sh920002 | 北交所 920 新段被判沪市，全线取不到 | bj920002 ✅ |
| `159915` | sh159915 | 深 ETF 判沪市，取不到 | sz159915 ✅ |
| `160216` | sh160216 | 取到 100.0 占位数据（真实 0.634），**取到了但取错** | sz160216 ✅ |
| `204001` | sz204001 | `"2" in "032"` 是字符串包含判断，2 开头被误判深市 | sh204001 ✅ |
| `200011` | sh200011 | 深 B 股判沪市 | sz200011 ✅ |
| `123138` | sh123138 | 深可转债判沪市 | sz123138 ✅ |

其中 `sh160216` 这类「取到了但取错」是最危险的变体：连报错都没有，只是数字不对。

## 四、缓存与性能

| 项 | 值 | 依据 |
|---|---|---|
| 分钟线 TTL | 15 秒 | 盘中足够新，同一只票 15 秒内重复请求不打数据源 |
| 快照 TTL | 3 秒 | 盘口要新，但也不能每击必中 |
| 空结果 | 不缓存 | 停牌/源抖动不能把「取不到」固化 |
| 全市场扫描 | ≈12 秒（3800 只 × 120 根 5m） | |
| 全市场快照 | ≈3.6 秒（4000 只，80/批分片） | |
| 单位 | volume 统一「手」，amount 统一「元」 | 腾讯 amount 原始是万元，适配层已折算 |

## 五、验证手段

```bash
# 1. 后端自检（14 步，含代码路由与有效性回归）
python3 -c "import sys; sys.path.insert(0,'server'); \
  import os; os.chdir('server'); import intraday; intraday.selfcheck()"

# 2. 接口自检
curl 'http://127.0.0.1:8899/api/intraday_selfcheck'

# 3. 浏览器端到端（29 步：分钟周期/摘要行/退回日线/扫描/跳转/全页签回归）
python3 scripts/e2e_intraday.py
```

端到端脚本覆盖的界面断言：

- 「分时看盘」页签与面板**确已下线**（防止误加回来）；
- 5 个分钟周期逐个切换：高亮正确、日线不高亮、提示条含根数、**canvas 恒为 1**（无实例泄漏）；
- 深度指标摘要行含「区间位置/量比/均线排列」；
- 再点同一周期退回日线：日线高亮恢复、提示条隐藏、摘要行清空；
- 条件选股页扫描全市场 → 点结果行 → 落到个股页且**带入扫描所用周期**。

自检覆盖的断言（防止回归）：

- 分钟聚合出的当日 OHLC 与实时快照逐位一致（最强正确性证据）；
- MA 与手工算术平均一致；当日切片根数 ≤ 一天容量；
- 各周期默认根数 ≥ 3 个交易日；扫描 120 根 ≥ 最长指标窗口 61 根；
- 12 个代码段归一化路由正确（920/159/204/200/11/12/…）；
- 5 个伪造代码被拦、8 个真实代码（含北交所老段/B 股）不被误杀。

## 六、已知边界

- **北交所分钟线**：eltdx 与腾讯都不支持。**业务上已明确不做**（2026-09 决定）——
  两家源都不覆盖，硬做只能靠拼接或造数据。前端保留体面降级：点北交所票的分钟按钮会明确提示
  「北交所股票暂不支持分钟线…可改用日线查看」，日 K 图原地保留、不白屏。
- **可转债分钟线**：代码有效、快照有，但分钟线接口取不到（404）。
- **五档盘口**：eltdx 只提供买一/卖一，不假装五档。原「分时看盘」页的买卖一档展示
  已随页签下线；若将来要恢复，数据源的档位字段仍在统一行情结构里（`bid_levels`/`ask_levels`）。
- **自动刷新**：原「分时看盘」页的 30/60 秒轮询已随页签**一并移除**。
  个股页分钟图不自动轮询——盘中要看最新数据，重进一次或切周期即可
  （单只缓存 15 秒，重复请求不会打数据源）。这样做是为了避免后台页面白刷数据源。
- **同花顺数据源**：实测其公开接口只有涨停池/人气榜/异动等特色数据，**不提供分钟 K 线**，
  对「分钟实时行情」这一场景没有兜底价值，暂不接入（2026-09 评估结论）。

## 七、市场温度的数据日期为什么不是今天

（截图：`docs/shot-market-temp-date.png`）

**现象**：页面「市场温度」卡片右上角显示 `温度画像 2026-09-21`，而当天是 09-22。

**结论：不是取数失败，是上游本来就是这样。** 实测上游原文为：

```
> 数据日期 `2026-09-21`（请求日期 2026-09-22，后端实际数据日期）
```

`market-overview`（13 维画像）由**通达信服务端在收盘后统一重算**，重算完成前返回的
仍是上一个交易日的画像 —— 上游自己标注为「后端实际数据日期」。旁证：

- 停牌股（`sh600193` 等）没有当日成交，两个源都取不到分钟线，
  间接印证 `market-overview` 的日期就是**上一交易日**（否则这些股当天应当有数据）。
- 同页面的**涨跌分布 / 成交额是实时的**：08 点多只样本股涨跌方向一致、
  上涨占比 41%，与 westock 声称的 44%（2374 涨 / 3030 跌）吻合，
  且成交额「较上日 +1040.37 亿」只有在当日**已收盘**（15:00 后）才拿得到。

**因此处理方式是「如实标注」而非「修掉」**：

| 层 | 改动 |
|---|---|
| `westock.py` | 增加解析「请求日期」，输出 `request_date` 与 `stale`；不再只给一个含糊的 `date` |
| `app.py` | `stale` 时补 `note` 字段，说明「滞后的是画像、实时的是涨跌」 |
| `index.html` | 卡片文案由 `数据日期 2026-09-21` 改为 **`温度画像 2026-09-21 · 涨跌实时`**，配色转警示色，鼠标悬停显示完整说明 |

**不要做的事**：不要把这个日期改成当天。画像滞后一天是上游的正常状态，
强行改成本地日期只会让人以为评分反映的是今天的盘面 —— 那是真正的误导。
