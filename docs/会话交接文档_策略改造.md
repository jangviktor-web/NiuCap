## 二、任务目标与背景

### 2.1 项目是什么

`tick-stock-panel`（牛来选股面板）是一个 A 股量化选股与择时分析工具：

- **后端**：FastAPI（`server/app.py`，55 个路由），Python 3.11
- **前端**：单文件 `web/index.html`（原生 JS + ECharts）
- **数据**：日线历史存 `data/tick.db`（SQLite），也支持 TiDB 云库（见 `.env`）
- **运行**：`server/run.py` 启动，默认端口 **8899**

### 2.2 本轮任务的目标

最初的任务是「接入 eltdx 作为日线历史数据源」，逐步演化为一条完整链路：

```
① 接入 eltdx 取数源（替换腾讯源）            ← 已完成
      ↓
② 跑全市场落库（覆盖率 8.1% → 100%）        ← 已完成
      ↓
③ 把 6 个「伪历史策略」改成真算历史指标       ← 已完成
      ↓
④ 在保证准确性的前提下调优阈值与验证         ← 已完成
```

**用户的核心约束**（原话）：

> 「好，**要确保数据和技术指标的准确性**的前提下落地优化」

「准确性」是这轮工作的第一原则，所有决策都以此为准绳。

### 2.3 什么是「伪历史策略」（问题的起点）

`screener.py` 里有 6 个策略，**名字上承诺要用历史数据，实际实现只看当日快照**：

| 策略 | 名字承诺 | 改造前的实际实现 |
|---|---|---|
| 突破新高 | 20 日新高 | `high >= prev*1.095` 且涨幅>5%（只看今日一根） |
| 均线多头 | MA 多头排列 | 涨幅 2%~8% + 换手 1%~15%（**完全没算均线**） |
| 平台突破 | 横盘后突破 | 涨幅 4%~9.9% + 非一字板（**没看是否横盘**） |
| 放量突破 | 放量 | 成交额≥3亿（**绝对额，不是相对自身均量**） |
| 超跌反弹 | 超跌 | 涨 1%~6% + 换手≥4%（**没看前期跌幅**） |
| 回踩企稳 | 回踩 MA20 | 涨跌 ±2% + 换手（**没算 MA20**） |

后果：`均线多头` 命中全市场 **30%**（1120/3761）——它根本不看均线，等于没筛选。

#### ③ 6 策略改造

**新增** `server/history.py`（506 行）—— 历史指标引擎，这是改造的技术核心：

```python
class HistoryEngine:
    def load(self, force=False):     # 一次 SQL 全表读（3.3s），非逐只查库
    def metrics(self, code, need=None):  # 取全套指标，数据不足返回 None
    def screen(self, pred, need=None):   # 批量筛选
```

**设计原则**：
- 指标算法与 `mytt.py` / `indicator.py` **保持一致**（通达信标准 `MA`/`HHV`/`LLV`/`REF`），不另写一套
- **数据不足返回 `None` 而非 0** —— 避免「数据不够却给出结论」的静默错误
- **进程内全量缓存 + 按交易日失效** —— 一天只加载一次，之后全是内存计算
- 内存：float32 numpy，**26.7 MB**（5565 只 / 146 万行）

**改造后命中数**（盘后基准，快照与历史同日对齐时）：

#### ④ 准确性验证（最重要，共四层）

**第 1 层 · 单元自检** `history.selfcheck()` **9/9 通过**，含与 `mytt.MA` 的交叉一致。

**第 2 层 · pandas 独立复算**：从 `daily_bars` 原表用 pandas 独立实现 6 个策略（不调用 `history.py` 任何函数），集合比对 —— **总分歧 0**。

**第 3 层 · 抓出并修复 2 个真实缺陷**（本轮最有价值的产出）：

**缺陷 A：float32 边界比较误判「平前高」为「破前高」**

- 现象：模块命中 450，pandas 命中 444，多 6 只
- 根因：float32 把 `5.10` 存成 `5.09999990`，`5.10 > 5.09999990` 成立 → 把「恰好等于前高」误判成「突破」
- 量化：450 只里突破幅度 < 1e-6 的正好 6 只；真实突破的幅度中位数是 +2.06%
- 修复：`screener.py` 新增 `_gt`/`_lt`/`_ge` 带容差比较（`EPS=1e-5`），`history.py` 的 `_last_ma` 求和提升到 float64
- 效果：450 → **444**，与 pandas 一致

**缺陷 B：区间振幅把「当日」算了进去**

- 现象：平台突破模块 34 只、pandas 39 只，且双向分歧
- 根因：`range60_pct` 用含当日的 60 根，但平台突破问的是「**突破之前**横不横」，当日放量大涨会撑大振幅
- 实证（被误杀的股票）：

| 代码 | 名称 | 不含当日振幅 | 含当日振幅 | 结果 |
|---|---|---|---|---|
| `sh600640` | 国脉文化 | 26.3% | **38.2%** | 超 35% 阈值 → 误杀 |
| `sz000532` | 华金资本 | 34.0% | **47.5%** | 误杀 |
| `sz000829` | 天音控股 | 33.7% | **38.6%** | 误杀 |
| `sz300559` | 佳发教育 | 33.1% | 35.0% | 卡在阈值上 |

- 修复：改为 `H[:-1]`（不含当日），与同模块的 `hhv60`/`llv20` 口径统一
- 效果：34 → **39**，与 pandas 一致

**第 4 层 · 阈值敏感性**（用数据选阈值，不拍脑袋）

平台突破振幅阈值：

| 振幅上限 | 命中数 | 占比 | 命中名单振幅中位 |
|---|---|---|---|
| ≤30% | 30 | 0.80% | 25.0% |
| **≤35%** | **39** | **1.0%** | **25.9%** ← 采用 |
| ≤40% | 49 | 1.30% | 27.9% |
| ≤45% | 58 | 1.54% | 33.5% |

选 35% 的理由：命中名单振幅中位仅 25.9%，说明真实平台突破天然远离阈值；
放宽到 45% 只多 19 只，但那些（36%~43%）已属「宽幅震荡」而非「平台」。

回踩企稳参数：

| 偏离区间 | 量比上限 | 命中占比 |
|---|---|---|
| ±1.5% | ≤0.8 | 8.1% |
| **±2%** | **≤0.85** | **~11.8%** ← 采用 |
| ±3% | ≤1.0 | 22.0% |

### 5.3 必读的注意事项（踩坑清单）

   `hfq` 偏差 193%。

4. **启动必须用 `python -u`**，否则 `nohup` 日志被缓冲，看起来像卡死（实际在跑）。

5. **`pkill -f "run.py"` 会误杀自己**——模式匹配到当前 shell 的命令行。用
   `ps aux | grep ... | awk '{print $2}' | xargs -r kill` 更安全。

6. **策略测试若在 `server/` 目录外跑**，`import store` 会失败（模块用的是平级 import）。
   必须在 `server/` 目录内，或加 `sys.path.insert(0, 'server')`。

7. **`history.py` 的回溯窗口 `LOOKBACK_DAYS=400`**（自然日）≈ 270 个交易日。
   MA60 需要至少 60 根，新股/停牌股会被自然排除（返回 None）。

8. **engine 是进程内单例**，`reload_engine()` 可在同步新数据后强制刷新。

9. **本项目不是 git 仓库**（`git status` 报错），改动没有版本控制兜底，改前先备份。

10. **`eltdx` 许可证是 ELTDX Research-Only License**，仅限个人学习/研究，禁止商用。
    这也是「全工程只有 `eltdx_source.py` 一个文件 import 它」的原因——便于隔离。

## 六、待解决的问题与风险

### 6.1 🔴 高优先级：盘中运行时快照与历史日期错位

**这是当前最需要知晓的风险。**

**现象**（2026-09-22 11:21 实测）：

| 数据 | 日期 |
|---|---|
| 历史日线 | **2026-09-21**（上一交易日收盘） |
| 行情快照 | **2026-09-22**（当前交易日盘中） |

策略把「快照的今日盘中价」与「截至昨日的指标」混在一起比较：

- `breakout_20h`：盘后基准 444 → 盘中 **568**
- `platform_break`：盘后基准 39 → 盘中 **19**

**已验证的对齐关系**：抽查 400 只，**398 只**的历史末根收盘 == 快照 `prev_close`
（唯一 2 只不等的是 `sh600379`、`sh600429` 除权股）。证明历史确实等于「昨日」。

**影响**：
- **盘后运行（推荐）**：当日日线已落库，快照与历史同日，**结果准确**
- **盘中运行**：指标基于昨日，当日涨跌未被纳入 → **命中数会漂移**

**可选的处理方向**（尚未实施，需用户决策）：

| 方案 | 说明 |
|---|---|
| A. 明确提示 | API 返回 `diag.data_lag_days`，前端显示「指标截至昨日」 |
| B. 盘中自动同步 | 盘中定时把当日快照写入日线，保证对齐 |
| C. 不处理 | 文档明确「策略面向盘后使用」，盘中仅供参考 |

### 6.2 ⚠️ 中优先级：北交所尚未纳入策略池

- 历史库已有 **344 只**北交所数据（价值实证：`bj920427` 库里 250 行 vs 腾讯源仅 1 行）
- 但快照池 `pool_rows()` 只有 **3761 只**，是 eltdx `all_a_shares()`（5575 只）的严格子集
- 缺的约 1814 只主要是**北交所（349 只）+ 次新股**

**影响**：策略扫描看不到北交所股票，尽管历史数据已经齐备。

**方向**：把 `datasource.pool_rows()` 扩展到 eltdx 全量代码表。
