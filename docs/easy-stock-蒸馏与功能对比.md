## 一、项目概况

| 项 | 内容 |
|---|---|
| 定位 | **A股 AI 智能投研工作台**（桌面应用，Local First） |
| 技术栈 | Go 后端 + React/TypeScript 前端 + **Electron 桌面壳** + 本地 **Hermes AI 运行时**（模型网关：OpenAI / DeepSeek / 通义千问 / Moonshot / Anthropic / 自定义 OpenAI 兼容） |
| 数据层 | Provider Registry 多源聚合（新浪行情、东财 K 线/资金/龙虎榜/F10、财联社资讯、腾讯指数/港股、华尔街见闻、同花顺 i 问财、雪球热门）、SQLite + 缓存快照、证据元数据（来源/时间/覆盖率/降级） |
| 架构分层 | 投研体验层 → 业务编排层(Go API) → AI Agent 平台层(Hermes) → 数据智能层 → 外部生态层 → 桌面运行边界 → 安全治理 |
| 体量 | ~143 commits，v1.2.2，活跃开发中（2026-08 起） |

**与牛来面板的关键差异**：easy-stock 是**桌面 Electron 单机应用 + LLM 投研**；牛来面板是**Web 面板（Python 后端 + 原生 JS 前端）**，已有量化/数据侧能力，但 AI/LLM 与"超短情绪/题材"侧较弱。两者数据源高度同源（东财/新浪/同花顺），**easy-stock 在"A股语境的结构化理解"上比牛来领先，是可重点吸收的方向。**

| # | 能力 | 本质 | 依赖 |

研究闭环：盘中发现 → 个股研判 → 持仓巡检 → 收盘复盘 → 信息收集 → AI 提炼 → 长期积累（记忆飞轮）。

## 三、后端 `internal/` 包结构（实现落点）

| 包 | 对应能力 | 关键文件 |
|---|---|---|
| `foundation` | 连板/题材/交易日历底座 | `trading_calendar.go`(**非交易日处理**)、`theme_progress.go`、`hot_stock.go`、`types.go` |
| `review` | **连板梯队 + 情绪周期**（"enhance ladder themes and handle non-trading days"） | （ladder 逻辑主落点） |
| `sector` | **题材雷达** | `radar_fusion.go`(**融合行业+开盘啦题材**)、`radar_strength.go`、`radar_identity.go`(去重)、`kaipanla_theme_mapping.go`、`industry_mapping.go` |
| `marketemotion` | 超短情绪 / 市场情绪指数 | — |
| `strategy/inflection` | **转折点分类(耗竭/轮动/反转) + 回测引擎**(手续费/滑点建模, ClickHouse 适配) | — |
| `portfolioinspection` | 持仓健康度巡检 | — |
| `providers` | 多源数据 Provider Registry（新浪/东财/财联社/腾讯/华尔街见闻/i问财/雪球） | — |
| `stockanalysis` / `narrative` / `methodology` / `hermes` | 个股AI分析 / 大V复盘 / 游资心法 / AI网关 | LLM 侧 |

**两个值得抄的"工程细节"**：
1. `trading_calendar.go` 单独处理**非交易日**——连板高度/晋级率若按自然日算会在周末/节假日崩，必须对齐交易日历。
2. `radar_fusion.go` 把**行业板块**和**开盘啦(kaipanla)题材**两套口径融合去重（`radar_identity.go`）——题材数据各家口径不一，融合+去重是做题材雷达的必经之路。

## 五、可优化进牛来的项（按性价比排序）

### 🥇 超短连板梯队 + 情绪周期（最高 ROI，纯计算）
- **抄什么**：涨停池、连板高度梯队、昨日涨停今日反馈（溢价/闷杀）、晋级率、情绪周期阶段（启动/发酵/高潮/退潮/冰点）。
- **牛来怎么落**：后端加一个 `limitup` 模块，从现有东财/同花顺涨停数据源拉涨停列表（已有行情源可复用），按交易日历（`trading_calendar` 思路）算连板天数与晋级；前端新增「连板」tab 或并入市场榜单工具栏。
- **坑**：必须对齐**交易日历**处理周末/节假日（easy-stock 的 `trading_calendar.go` 已踩过）。
- **不依赖 LLM、不依赖新数据源授权**，ROI 最高。

### 🥈 趋势题材雷达（高 ROI，纯计算）
- **抄什么**：题材/概念板块的"涨幅强度 + 资金流 + 上涨宽度 + 持续天数"多维评分；产业链/概念节点拆解；行业板块与题材双口径**融合去重**。
- **牛来怎么落**：后端加 `theme_radar` 模块，聚合东财行业板块 + 同花顺/开盘啦题材（现有数据源够用），复用 easy-stock 的 `radar_fusion`/`radar_identity` 思路做去重融合；前端做雷达/热力图。
- **坑**：题材命名各家不一，必须有 identity/归一映射层，否则同题材重复计数。

### 🥉 龙虎榜 / 机构席位（中高 ROI，纯计算）
- **抄什么**：每日龙虎榜（游资席位、机构买入、一日榜/三日榜）、资金净流入。
- **牛来怎么落**：东财龙虎榜接口已在 easy-stock 的 providers 里验证可用；牛来接入后做"龙虎榜"卡片，和个股分析联动。

### 持仓健康度巡检（中 ROI，复用虚拟盘，无需 LLM）
- **抄什么**：确定性健康度评分（个股质量/风险韧性/分散程度/风格匹配）+ 集中度/联动/止损风险识别。
- **牛来怎么落**：直接读**虚拟盘持仓**（#T+1 修复后数据规范），加一个 `portfolio_health` 评分函数（纯规则，不引 LLM），前端在虚拟盘页加"组合体检"。
- **价值**：牛来已有持仓数据，几乎是零成本增量。

### 公告雷达（中 ROI，纯计算）
- **抄什么**：个股/持仓相关公告聚合（业绩、减持、重组、停牌）。
- **牛来怎么落**：东财 F10/公告源；对自选/持仓做"公告雷达"提醒，可复用监控中心推送通道。

### 数据可信度 / 证据可追溯（UX 原则，低成本）
- **抄什么**：每个数据块标注**来源 + 抓取时间 + 覆盖率 + 降级状态**（easy-stock 的"证据元数据"哲学）。
- **牛来怎么落**：在现有快讯/行情卡片补"数据来源 + 更新时间"小角标；监控中心已有降级逻辑，可外显。
- **价值**：极低改动、显著提升可信度，契合牛来"可解释"定位。

### 转折点分类 + 回测增强（中 ROI，增强已有回测）
- **抄什么**：把信号分成耗竭/轮动/反转等类型，`next-bar` 回测带手续费/滑点建模。
- **牛来怎么落**：牛来已有策略回测，可吸收"信号分型 + 费率/滑点建模"思路增强。
